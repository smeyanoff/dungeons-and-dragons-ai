**Файл:** `build/Dockerfile:34`

**Проблема:** 
```dockerfile

**Риск:** Использование `latest` может привести к непредсказуемым обновлениям и проблемам совместимости при пересборке образов.

```

## 🟡 Средние проблемы

### 2. Dockerfile: Незафиксированные версии пакетов в apk

**Файл:** `build/Dockerfile:5, 36`

**Проблема:**
```dockerfile
RUN apk add --no-cache git ca-certificates tzdata
RUN apk --no-cache add ca-certificates tzdata wget
```

**Риск:** Непредсказуемые обновления пакетов могут привести к проблемам совместимости или безопасности.

**Решение:** Зафиксировать версии пакетов:
```dockerfile
RUN apk add --no-cache git=2.43.0-r1 ca-certificates=20240226-r0 tzdata=2024a-r0
RUN apk --no-cache add ca-certificates=20240226-r0 tzdata=2024a-r0 wget=1.21.4-r3
```

**Примечание:** 
- Версии должны периодически обновляться для устранения уязвимостей
- В Alpine Linux фиксация точных версий пакетов не всегда рекомендуется, так как версии могут отличаться на разных архитектурах
- Альтернатива: регулярное сканирование уязвимостей через Trivy и обновление базового образа Alpine
- Текущее решение: используем фиксированную версию Alpine 3.18, которая автоматически получает обновления безопасности через репозиторий

**Статус:** ⚠️ Частично решено (зафиксирована версия Alpine), версии пакетов не зафиксированы (рекомендуется для Alpine)

### 4. Gosec: Integer overflow conversions (CWE-190)

**Файлы:** 
- `internal/rag/infrastructure/vectorstore/qdrant.go:99, 118, 131`
- `pkg/gigachat/auth.go:151`

**Проблема:** Преобразования типов без проверки на переполнение:
- `uint` → `int64` (может быть отрицательное значение)
- `int` → `uint64` / `uint` (может быть переполнение)

**Риск:** HIGH - Integer overflow может привести к непредсказуемому поведению, ошибкам выполнения или уязвимостям безопасности.

**Пример:**
```go
IntegerValue: int64(doc.SessionID)  // uint -> int64
limitUint64 := uint64(limit)        // int -> uint64
backoff := initialBackoff * time.Duration(1<<uint(attempt-1))  // int -> uint
```

**Решение:** 
- Добавить проверки диапазонов перед преобразованием
- Использовать `strconv` для безопасных преобразований
- Добавить валидацию значений перед использованием

**Статус:** ⚠️ Требует исправления

### 5. Gosec: Weak random number generator (CWE-338)

**Файл:** `internal/game/domain/dice/dice.go:60`

**Проблема:** Использование `math/rand` вместо `crypto/rand`:
```go
rng := rand.New(rand.NewSource(time.Now().UnixNano()))
```

**Риск:** HIGH - Детерминированный генератор случайных чисел не подходит для криптографических целей и может быть предсказуемым.

**Примечание:** Для игры в кости (`dice`) это может быть приемлемо, но лучше использовать `crypto/rand` для безопасности.

**Решение:**
```go
// Использовать crypto/rand для криптографически стойкого генератора
import "crypto/rand"
```

**Статус:** ⚠️ Требует исправления (низкий приоритет для игры в кости)
