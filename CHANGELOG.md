# Changelog

Все значимые изменения проекта фиксируются в этом файле.

## [v1.0.0-alpha] — 2026-07-26

Первый релиз, объединяющий накопленные в `dev` изменения в `main`.

### Добавлено

- **Стартовое снаряжение и золото при создании персонажа.** `CreateCharacterUseCase` теперь собирает классово-специфичный стартовый инвентарь (оружие и броня экипируются сразу, плюс зелья/инструменты и немного золота) и сохраняет его сразу после создания персонажа. У `Inventory` появилось поле `Gold`, `/inventory` отображает его.
- **Идентичность NPC как факт кампании (`npc_identity`).** Новая категория `CampaignFact`, фиксирующая, кто есть кто (имя + роль/родство), чтобы DM не противоречил себе при повторном упоминании NPC. Инструмент `save_campaign_fact` явно инструктирует DM записывать эту информацию при первом появлении NPC; `dm_analyzer` дополнительно генерирует такой факт автоматически по `npc_met` как пассивная защита на случай, если DM не вызвал инструмент.
- **Идентичность NPC заполняется уже на этапе генерации мира**, а не только во время игры: `NPCDTO` получил поле `Relation`, промпт генерации локаций/NPC запрашивает родственные/ролевые связи, и `InitCampaignUseCase` сразу пишет `npc_identity`-факты для NPC со связями — ещё до первого хода игрока.
- **DM-инструмент `move_to_location`.** Раньше позиция на карте и игровое время/погода продвигались только через явную UI-навигацию; теперь DM может сам инициировать сюжетное перемещение партии свободным текстом («иду в лес»), и `/map`, время и погода синхронизируются с повествованием. Инструмент переиспользует существующую логику `worldmap.MoveToLocationUseCase` (связность локаций, расчёт времени в пути).
- **Очистка данных сессии в Qdrant (RAG) при завершении игры.** У `VectorStore` появился метод `Delete` (delete-by-filter на `session_id`), плюс payload-индексы на `session_id`/`location_id` для ускорения фильтрации. Новый use case `DeleteSessionData` вызывается при `/newgame` поверх старой завершённой сессии того же чата. Добавлен интеграционный тест на изоляцию сессий в реальном Qdrant.
- **Навык `read-dnd-bot-logs`** для Claude Code — curl+jq драйвер поверх JSON-эндпоинтов `internal/monitoring/server.go` (stats/recent/chat/user/session/errors/branches/show/metrics) для чтения логов LLM-запросов прод-бота.

### Исправлено

- **Проверка навыка (ability check) больше не блокируется после смены локации.** `RequestAbilityCheckTool` сканировал последние 50 событий сессии целиком без учёта локации, из-за чего успешно пройденная проверка (например, Интеллекта) блокировала повторную такую же проверку уже в другой локации. Теперь события фильтруются по `CurrentLocationID`, поведение для событий без привязки к локации не изменилось.
- **Восстановлен приоритет блоков «память локации» / «факты кампании» при обрезке промпта DM.** После переименования и добавления новых RAG-блоков контекста (`Память этой локации`, `Ключевые факты кампании`) приоритеты обрезки (`contextBlockPriority`/`summarizeBlockContent`) не были обновлены, из-за чего эти блоки попадали в грубую обрезку по умолчанию раньше менее важных данных. Приоритет выровнен с «Последние сообщения»/«Персонаж игрока», для «Память этой локации» используется структурная суммаризация вместо обрезки посередине строки.
- **Осиротевшие данные кампании больше не остаются в БД после `/endgame` → `/newgame`.** `GameSessionRepository.Delete()` удалял только `Player` и `SessionGoal` завершённой игры; `StoryEvent`, `Combat`/`CombatParticipant`, `CampaignFact`/`WorldEvent` оставались в базе (не читались новой сессией, но нарушали инвариант «одна кампания = самодостаточный набор данных»). Теперь всё это удаляется в той же транзакции.

### Изменено / производительность

- **Возраст-зависимое сжатие истории сообщений в контексте DM.** Вместо одинакового лимита символов (800) для каждого сообщения в окне недавних событий, теперь бюджет символов уменьшается вдвое с каждым более старым сообщением вплоть до минимального порога (`RAG_MIN_EVENT_CHARS`, по умолчанию 150) — недавние реплики остаются подробными для непрерывности повествования, старые сжимаются до кратких строк. Без дополнительных LLM-вызовов, экономит токены на длинных сессиях.

### Тесты

- Регрессионный интеграционный тест на повторную проверку навыка после смены локации (`TestAbilityCheck_Guardrails_AlreadyChecked_DifferentLocation`).
- Тесты на приоритет и суммаризацию блоков контекста при обрезке промпта.
- Тест на изоляцию сессий в Qdrant (`rag_session_isolation_test.go`).
- Тест `TestSeedNPCIdentityFacts` на заполнение идентичности NPC при генерации мира.
- Обновлены миграции тестов персистентности игровой сессии под новые каскадные удаления (`StoryEvent`, `Combat`, `CombatParticipant`, `CampaignFact`).
