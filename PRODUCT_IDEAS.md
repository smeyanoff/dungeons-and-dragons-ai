# Продуктовые идеи для D&D AI Telegram Bot (DM + RAG)

**Последнее обновление:** 2026-02  
**Связь:** статусы задач — `TASKS.md`, фидбек — `FEEDBACK.md`.

---

## Продуктовые принципы (не ломать)

- **Проверки редкие и значимые**: только при stakes + понятная причина; guardrails важнее промпта.
- **Нет system/tool текста игроку**: 0 утечек internal/JSON/tool в ответах DM.
- **Непрерывность сессии**: после проверок/боёв игра продолжается без ручных разблокировок.
- **Темп важнее детализации**: игрок всегда понимает "что делать дальше".

---

## ✅ Реализовано (2026-02, по TASKS.md)

- Авто-изображения выключены по умолчанию (`/autoimage on/off`).
- Tools-loop для DM: multi-step инструменты + очистка tool-артефактов из ответа.
- Навигация по карте кнопками (inline `map_to_*`), visited-локации на `/map` и в навигации.
- Единый output-guard перед Telegram: 0 утечек player-facing текста + тесты.
- При перемещении pending ability check очищается (навигация не "залипает").
- RAG fallback: при timeout — резюме сцены + уточняющий вопрос (без "забывания").
- GigaChat 402: typed ошибка + упрощённый режим (игра не блокируется).
- Повтор проверки ограничен сценой; после смены локации проверка снова допустима.
- Flaky tests убраны (без `time.Sleep`); bot.go < 1500 LOC, команды синхронизированы.
- Спринт P1 1–7 и P2.A закрыты (см. TASKS.md архив).
- **P1 2026-02-09:** OOC мета-интенты (isOOCMetaQuery, ответ без cooldown/проверок); контроль медиа (лимит изображений на сессию в GameSession, мягкое сообщение при лимите, автоген только для локации/NPC, описание инструмента generate_image); combat guard (CombatFallbackMessage при пустом списке врагов).
- **P2 2026-02-09:** Playbook локаций (LocationScenario: hook, key_events, critical_choice, possible_outcomes, related_npc/quest_item; ENABLE_PLAYBOOK_GENERATION); пояснимость проверок (промпт DM + request_ability_check); лимит изображений на сессию + значимое событие (combat_ended); резюме сессии (/summary, /resume); метрика checks per 100 msg (SessionMessageCount, логирование при >5); мониторинг (402 в GetMetrics, RAG/output-leak счётчики, /api/metrics).

## Roadmap (что делать дальше)

### P0 — должно работать всегда ✅ (2026-02-09)

- **Мета-интенты (OOC)** ✅: "где я / что вокруг / опиши место / резюме" → ответы DM без cooldown/проверки (isOOCMetaQuery).
- **Контроль медиа** ✅: изображения только по явному запросу или крупному событию; лимит на сессию (GameSession.ImagesGeneratedInSession); автоген только локация/NPC; мягкое сообщение при лимите.

### P1 — качество и предсказуемость

- **Playbook локации** ✅: hook → 2–4 сцены → критический выбор → последствия; связь с NPC и квестовыми предметами (LocationScenario, ENABLE_PLAYBOOK_GENERATION).
- **Пояснимость проверок** ✅: "почему" + "что на кону" в 1–2 предложениях (промпт DM + request_ability_check).
- **Единый UX боёв** ✅: защита от пустых `enemies` при `combat_detected=true` (CombatFallbackMessage).

### P2 — retention (1–2 фичи на квартал)

- **Сессионные цели**: цель на 10–20 минут + итог/награда.
- **Динамические квесты**: ветвление от решений, последствия в мире.
- **Репутация NPC**: отношения открывают/закрывают опции.

### P3 — социальность (после стабилизации)

- **Кооператив 2–3 игрока**: очередь решений + общий журнал.
- **Шаринг**: карточка приключения/цитата/ачивка.

### P4 — опционально

- **TTS** для ключевых сцен (лимитируемо).

## Минимальные метрики качества

- **Утечки system/tool**: 0 (обязательная фильтрация).
- **Checks per 100 сообщений**: <5, каждая с stakes/reason.
- **RAG timeout → "забывание"**: 0 (деградация: резюме/уточнение, не сброс контекста).

## Почему это важно (ключевой фидбек, FEEDBACK.md)

- Проверки должны быть редкими и значимыми — иначе теряется доверие к DM.
- Утечки internal-текста ломают immersion; медиа слишком часто — теряется предсказуемость.
- Провалы RAG воспринимаются как "DM забыл"; навигация не должна блокироваться проверками.
- Пользователям нравятся: атмосферные описания, связность мира, бои "когда корректно распознаны", стабильный RAG.
