### 9. Генерация изображений локаций, предметов и персонажей через GigaChat
**Описание:** Визуальное представление игры через генерацию изображений с помощью GigaChat API

**Механика:**
- Интеграция с GigaChat API для генерации изображений (если поддерживается) или альтернативные API (DALL-E/Midjourney/Stable Diffusion)
- Автоматическая генерация изображений для локаций при первом посещении
- Генерация изображений предметов при получении их игроком (карта, меч, зелье и т.д.)
- Генерация изображений персонажей (визуализация персонажа игрока на основе расы, класса, характеристик)
- Генерация изображений NPC при встрече
- Команда `/image` для регенерации изображения локации/NPC/предмета

**Типы генерации:**
1. **Локации** - изображения мест, где находится игрок ("подвал с сундуком", "лесная поляна", "таверна")
2. **Предметы** - визуализация предметов из инвентаря ("карта с отметками", "старый меч", "зелье лечения")
3. **Персонажи** - визуализация персонажа игрока на основе расы, класса, снаряжения
4. **NPC** - изображения NPC при встрече ("лучник в маске", "старый торговец")

**Технические детали:**
- Проверить поддержку генерации изображений в GigaChat API (возможно через `/images/generations` endpoint)
- Если GigaChat не поддерживает - использовать альтернативные API (DALL-E, Stable Diffusion через Hugging Face API)
- Создать `ImageGenerationUseCase` в `application/image/` или интегрировать в существующие use cases
- Сохранение изображений: локальное хранилище или CDN (S3, Cloudflare R2)
- Кэширование изображений для повторного использования (по описанию локации/NPC/предмета)
- Интеграция с Telegram для отправки изображений через `SendPhoto` API

**Пример промпта для генерации:**

### 10. MCP-подобный функционал для DM (Tools/Function Calling) ⭐ АРХИТЕКТУРНАЯ ОСНОВА
**Описание:** Система, позволяющая DM вызывать функции работы с игровыми системами напрямую во время генерации ответа, аналогично Model Context Protocol (MCP). Все игровые механики должны быть реализованы как DM Tools для полного контроля DM над игрой.

**Детали:**
- DM может вызывать функции для работы с инвентарем (`get_inventory`, `add_item`, `remove_item`)
- Получение характеристик персонажа через `get_character_stats`
- Проверка и управление боем через `check_combat_status`
- Начисление опыта через `add_experience`
- Система "tools" (функций), расширяемая для новых игровых механик

**Преимущества:**
- Более точный контроль над игровым состоянием
- DM получает актуальную информацию ДО генерации ответа
- Нет необходимости парсить JSON из текста ответа
- Расширяемость - легко добавлять новые tools
- Соответствие современным практикам (OpenAI Functions, Anthropic Tools, MCP)

**Реализация:**
- Если GigaChat API поддерживает function calling - использовать напрямую
- Если нет - реализовать multi-step loop: генерация → анализ → вызов функций → повторная генерация

**Ценность:** Улучшает точность и надежность работы DM, упрощает добавление новых игровых механик

**Монетизация:** Базовый функционал (бесплатно), расширенные tools для премиум

**Статус:** ✅ **РЕАЛИЗОВАНО** (Январь 2025)

**Реализовано:**
- Создан пакет `dm_tools` с архитектурой инструментов
- Реализованы инструменты: `get_inventory`, `add_item_to_inventory`, `remove_item_from_inventory`, `get_character_stats`, `check_combat_status`
- Реализован multi-step loop для работы с tools через промпт
- Интегрировано в `HandleActionUseCase` с автоматической регистрацией tools

### 62. Команда /help и меню команд бота для просмотра доступных команд
**Описание:** Добавить команду `/help` и настройку Bot Commands Menu в Telegram для легкого доступа к списку команд

**Проблема (из FEEDBACK):**
- Пользователь должен каждый раз писать `/start` чтобы увидеть список доступных команд
- Нет постоянного доступа к списку команд в интерфейсе бота
- Telegram Bot Commands Menu не настроен, поэтому команды не отображаются автоматически

**Решение:**
- Добавить команду `/help` которая показывает список всех доступных команд (дублирует `/start` но с более коротким описанием)
- Настроить Bot Commands Menu в Telegram через API (`setMyCommands`) - команды будут отображаться в меню рядом с кнопкой ввода
- Команда `/help` должна показывать все команды с кратким описанием
- Меню команд Telegram будет доступно через кнопку меню в интерфейсе бота

**Технические детали:**
- Добавить обработчик команды `/help` в `bot.go` → `handleCommand()`
- Реализовать `handleHelp()` метод - показывает список команд (можно использовать тот же текст что и в `handleStart()`)
- Настроить Bot Commands Menu через `api.SetMyCommands()` при инициализации бота
- Команды для меню:
  ```
  /start - Начало работы
  /help - Список команд
  /newgame - Начать игру
  /character - Персонаж
  /inventory - Инвентарь
  /quests - Квесты
  /map - Карта
  /roll - Бросить кубик
  /attack - Атаковать
  ```

**Преимущества:**
- Быстрый доступ к командам через меню Telegram (не нужно вводить `/start`)
- Команда `/help` всегда доступна для просмотра команд
- Улучшает UX - пользователь видит доступные команды в интерфейсе

**Ценность:** Критично для UX, снижает барьер входа, пользователь всегда знает доступные команды

**Монетизация:** Базовый функционал (бесплатно)

**Приоритет:** 2 (средний - улучшение UX, не критично но важно)
