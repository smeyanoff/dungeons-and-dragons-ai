## Текущий продуктовый фокус (P0): “событие локации → (возможно) проверка → бросок игроком”

### Проблема
- **Промпт‑инструкции не лечат механику**: DM начинает **спамить проверками**, темп ломается, игрок раздражён.

### Цель
- Проверка — это **решение анализатора/рантайма**, а система гарантирует:
  - **текстовый UX** (без кнопок),
  - **обязательные reason + stakes**,
  - **ограничители** (budget/cooldown/anti‑trivial),
  - корректный **pending → roll → resolve** цикл.

### Жёсткие UX‑принципы ✅ (реализовано)
- **Text-only**: взаимодействие игрока с миром и механиками — **сообщениями**.
- Игрок **не инициирует проверки**: pending check создаёт только система (анализатор).
- DM **не просит /roll и не "запрашивает проверки"** — он только ведёт художественный текст.
- DM **не показывает "внутреннюю кухню"**: никаких служебных строк, трассировки, таблиц DC, "predefined checks" в тексте сцены.

### Мини‑контракт поведения (player-facing)
- Если **нет** pending check:
  - `/roll` = просто бросок (без резолва проверок).
  - “15”/“результат 15” = обычное сообщение (не бросок/не проверка).
- Если pending check **есть**:
  - `/roll` резолвит **ровно 1** pending check и очищает ожидание.
  - повторный `/roll` без нового pending check ничего не резолвит.

## Backlog по приоритетам

### P0 — “должно просто работать”
- **Location events lifecycle**: 0..N событий на локацию, статусы `pending/resolved/expired`, запись в историю и в RAG.
- **Analyzer-first checks**: анализатор решает “нужна ли проверка” и создаёт pending check (ability, DC, reason, stakes) **без участия LLM-DM** и без tool-инструкций в контексте.
- **Text roll UX**: `/roll` / `/roll d20` (+ опциональный парс “roll d20”, “кидаю с преимуществом”; ручной ввод результата — только при pending check).
- **Guardrails**: budget/cooldown/anti‑trivial + “reason+stakes required” (и сохраняются в историю).

### P1 — качество/погружение/стабильность
- **Санитизация ответов**: полностью убрать утечки tool‑текста/JSON/служебных строк из player-facing сообщений.
- **Починка `/battlefield`**: прозрачность боя и удобный дебаг.
- **Стабильность JSON‑контрактов**: меньше repair/fallback, никаких “безымянных врагов”/битых полей, чтобы бой не разваливался.
- **Улучшить UX проверок навыков**:
  - `/roll` без аргументов автоматически бросает d20.
  - После проверки DM автоматически продолжает повествование.
  - Исправить несоответствия в описании проверок (восприятие vs мудрость).

### P2 — рост и удержание (после стабильного P0/P1)
- **Ежедневки/стрик**: мягкие награды/цели.
- **Мини‑ивенты**: короткие сценки в локациях **без обязательных чеков**.

### P3 — социальность/вирусность (позже)
- **Партия/мультиплеер** (очередь, совместные решения, бой).
- **Лидерборды** (когда появятся стабильные метрики).
- **Гильдии** (когда устойчивый retention).

### P4 — “вау” визуализация
- **Изображения** (локации/NPC/предметы) как дополнительный слой.
- **Улучшенная карта** (связи, выделение текущей локации).
