# Продуктовые идеи для D&D AI Telegram Bot (DM + RAG)

**Последнее обновление:** 2026-02  
**Назначение:** единый короткий backlog. Статусы задач — `TASKS.md`, фидбек — `FEEDBACK.md`.

---

## Продуктовые принципы (то, что нельзя сломать)
- **Редкие и значимые проверки**: проверки только когда есть stakes + понятная причина (guardrails важнее “промпта”).
- **Никакого “системного мусора” игроку**: запрещены утечки tool/internal текста в ответы DM.
- **Непрерывность сессии**: после проверок/боёв игра должна продолжаться без ручных “разблокировок”.
- **Темп важнее детализации**: игрок всегда понимает “что делать дальше” и не упирается в неочевидные ограничения.

---

## ✅ Недавно реализовано (2026‑02)
- **Авто‑изображения выключены по умолчанию**: игрок сам включает через `/autoimage on/off`.
- **Tools‑loop для DM**: поддержка multi‑step инструментов + базовая очистка tool‑артефактов из ответа.
- **Навигация по карте кнопками**: inline переходы (callback `map_to_*`) для понятного UX перемещения.
- **Анти‑утечки player‑facing текста**: единый output‑guard на Telegram pipeline + тесты.
- **Visited‑локации**: отметки посещённого на `/map` и в inline‑навигации.
- **Pending check не “залипает”**: при перемещении pending ability check очищается.
- **RAG деградация без “забывания”**: fallback (резюме сцены + уточняющий вопрос).
- **GigaChat 402**: typed ошибка + “упрощённый режим” (игра не блокируется).
- **Повтор проверки ограничен сценой**: после смены локации проверка снова допустима.

## Roadmap (что делать дальше)

### P0 — должно работать “всегда”
- **Мета‑интенты (OOC) распознаются**: “где я / что вокруг / опиши место / резюме” → безопасные ответы DM, не как реплика персонажа.
- **Контроль медиа**: изображения только по явному запросу/крупному событию; лимиты на сессию; выключить автогенерацию карты как базовый UX.

### P1 — качество и предсказуемость
- **Playbook локации**: hook → 2–4 сцены → критический выбор → последствия/награда; обязательно использовать уже существующих NPC и квестовые предметы.
- **Пояснимость проверок**: “почему” + “что на кону” в 1–2 предложениях.
- **Единый UX боёв**: предсказуемый вход/выход, защита от пустых `enemies` при `combat_detected=true`.

### P2 — retention (1–2 фичи на квартал)
- **Сессионные цели**: чёткая цель на 10–20 минут + итог/награда.
- **Динамические квесты**: ветвление от решений, последствия в мире.
- **Репутация NPC**: отношения открывают/закрывают опции.

### P3 — социальность (после стабилизации)
- **Кооператив 2–3 игрока**: очередь решений + общий журнал.
- **Шаринг моментов**: карточка приключения/цитата/ачивка.

### P4 — “вау” (опционально)
- **TTS** для ключевых сцен (опционально, лимитируемо).

## Минимальные метрики (для контроля качества)
- **Утечки system/tool текста**: 0 (обязательная фильтрация).
- **Checks per 100 сообщений**: <5 (и каждая с stakes/reason).
- **RAG timeout → “забывание”**: 0 (должен быть деградационный режим: резюме/уточнение, но не провал контекста).
