## 🔴 Критические проблемы

### 1. Неправильный расчет урона и отображение HP/AC/броска в бою

**Источник:** FEEDBACK.md #1, логи production  
**Приоритет:** 🔴 Критический  
**Статус:** ⚠️ **Требует срочного исправления** (Январь 2025)

**Проблема:**
- После нанесения урона система показывает неправильные значения HP, AC и броска атаки
- Пример: было 2/6 HP, нанесено 4 урона → система показывает "HP: 0/0" вместо "0/6"
- AC и бросок атаки показывают 0 вместо реальных значений
- **В логах:** DM Analyzer получает от LLM `hp: 0` для стражника, что приводит к созданию участника боя с `MonsterHP = 0`

**Найденная причина:**
1. **DM Analyzer создает бой с HP=0:** Когда DM Analyzer получает от LLM JSON с `hp: 0`, бой создается через `handleCombatStart` с `MonsterHP = 0`
2. **Активный бой не найден:** В логах видно `record not found` - активный бой завершен или не сохранен, поэтому информация о HP не попадает в контекст для DM Analyzer
3. **Неполная загрузка данных:** В `CombatRepository.GetActiveBySessionID()` отсутствует `Preload("Participants.Character.Stats")` для корректной загрузки характеристик
4. При применении урона через `ApplyDamageTool` состояние может не обновляться корректно

**Частичные исправления (Январь 2025):**
- ✅ Добавлена проверка в `handleCombatStart`: если `enemy.HP <= 0`, используются значения по умолчанию (HP=10, AC=12, AttackBonus=2)
- ✅ Враги без имени пропускаются при создании боя
- ⚠️ Но проблема остается: неправильная загрузка характеристик из БД

**Требуется исправление:**
- Добавить `Preload("Participants.Character.Stats")` в `CombatRepository.GetActiveBySessionID()`
- Проверить сохранение состояния боя после применения урона в `combat_tool.go`
- Проверить, почему активный бой не сохраняется или завершается преждевременно
- Добавить валидацию значений перед отображением (HP/AC не должны быть 0 для живых монстров)

**Файлы для изменения:**
- `internal/game/infrastructure/persistence/combat.go` - добавить Preload для Stats
- `internal/game/application/dm_tools/combat_tool.go` - проверка сохранения после урона
- `internal/game/application/dm_analyzer/analyze_dm_response.go` - уже исправлено создание участников с HP=0
- `internal/game/domain/combat/combat.go` - методы GetHP(), GetAC()

**Связано:** FEEDBACK.md #1, логи production, TASKS.md #64

## ⚠️ Важные проблемы (требуют исправления)

### 2. DM выдумывает союзников/товарищей в бою, которых нет

**Источник:** FEEDBACK.md #2  
**Приоритет:** Высокий  
**Статус:** ⚠️ Требует исправления

**Проблема:** DM описывает союзников/товарищей игрока в бою, которых нет в реальной игровой сессии.

**Решение:**
- Добавить в контекст RAG явное указание количества игроков в сессии: "Количество игроков: 1 (игрок один)"
- Добавить инструкцию для DM: "Используй ТОЛЬКО реальных участников боя из списка выше. Не выдумывай союзников или товарищей, которых нет в списке участников боя"
- При перечислении участников боя явно указывать, сколько игроков и сколько врагов

**Технические детали:**
- Расширить `RAGContextBuilder.BuildContext()` для подсчета игроков в сессии
- Добавить явное указание в контекст: "Игроков в бою: X, Врагов: Y"

**Файлы для изменения:**
- `internal/game/infrastructure/context/rag_context_builder.go`

**Связано:** FEEDBACK.md #2

### 3. Валидатор блокирует поднятие предметов из мира

**Источник:** FEEDBACK.md #4  
**Приоритет:** Высокий  
**Статус:** ⚠️ Требует исправления

**Проблема:** Валидатор действий блокирует действие "взять" для предметов из мира, ошибочно считая, что предмет должен быть в инвентаре.

**Решение:**
- Исключить действие "взять" из проверки в `checkEmptyInventoryItemUsage()` для пустого инвентаря
- "Взять" должно интерпретироваться как подбор предмета из мира, а не использование предмета из инвентаря
- Различать действия: "использовать [предмет]" (из инвентаря) vs "взять [предмет]" (из мира)

**Технические детали:**
- Убрать "взять" из списка `itemActions` в `checkEmptyInventoryItemUsage()` (строка ~140)
- При пустом инвентаре разрешать действие "взять" - оно означает подбор из мира

**Файлы для изменения:**
- `internal/game/application/player_action/action_validator.go`

**Связано:** FEEDBACK.md #4

### 4. DM Analyzer - периодические ошибки парсинга JSON от LLM

**Источник:** Логи production  
**Приоритет:** Важный  
**Статус:** ⚠️ Требует улучшения

**Проблема:**
- LLM иногда обрезает JSON ответ (не завершает его полностью)
- За последние 24 часа: **13 случаев** невалидного JSON после всех попыток восстановления

**Влияние:**
- Fallback механизм работает (возвращает пустой анализ), система не падает
- Но система не может определить боевые ситуации, квесты и опыт в этих случаях

**Рекомендации по улучшению:**
- Увеличить `max_tokens` для DM Analyzer (сейчас 512)
- Улучшить промпт с более четкими инструкциями о завершении JSON
- Добавить проверку на обрезанный JSON и автоматическое завершение структуры

**Файлы для изменения:**
- `internal/game/application/dm_analyzer/analyze_dm_response.go:142` - увеличить max_tokens

**Связано:** TASKS.md #2 (частично решено, но требует доработки)
