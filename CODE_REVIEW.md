## ⚠️ Проблемы безопасности (требуют исправления)

### 1. Integer overflow conversions (CWE-190)

**Файлы:** 
- `internal/rag/infrastructure/vectorstore/qdrant.go:99, 118, 131`
- `pkg/gigachat/auth.go:151`

**Проблема:** Преобразования типов без проверки на переполнение:
- `uint` → `int64` (может быть отрицательное значение)
- `int` → `uint64` / `uint` (может быть переполнение)

**Риск:** HIGH - Integer overflow может привести к непредсказуемому поведению или уязвимостям безопасности.

**Примеры:**
```go
IntegerValue: int64(doc.SessionID)  // uint -> int64
limitUint64 := uint64(limit)        // int -> uint64
backoff := initialBackoff * time.Duration(1<<uint(attempt-1))  // int -> uint
```

**Решение:** 
- Добавить проверки диапазонов перед преобразованием
- Использовать `strconv` для безопасных преобразований
- Добавить валидацию значений перед использованием

**Статус:** ⚠️ Требует исправления

**Связано:** PROBLEMS.md #4

### 2. Weak random number generator (CWE-338)

**Файл:** `internal/game/domain/dice/dice.go:60`

**Проблема:** Использование `math/rand` вместо `crypto/rand`:
```go
rng := rand.New(rand.NewSource(time.Now().UnixNano()))
```

**Риск:** HIGH - Детерминированный генератор случайных чисел может быть предсказуемым.

**Примечание:** Для игры в кости (`dice`) это может быть приемлемо, но лучше использовать `crypto/rand` для безопасности.

**Решение:**
```go
import "crypto/rand"
// Использовать crypto/rand для криптографически стойкого генератора
```

**Статус:** ⚠️ Требует исправления (низкий приоритет для игры в кости)

**Связано:** PROBLEMS.md #5

## ⚠️ Важные проблемы (требуют исправления)

### 4. DM Analyzer - периодические ошибки парсинга JSON от LLM

**Источник:** Логи production (docker logs)  
**Приоритет:** Важный  
**Статус:** ⚠️ Требует улучшения

**Проблема:**
- За последние 24 часа: **13 случаев** невалидного JSON после всех попыток восстановления
- LLM иногда обрезает JSON ответ (не завершает его полностью)
- Примеры обрезанных JSON:
  - `"items_received":` без закрывающей скобки
  - JSON обрывается в середине массива `enemies`
  - LLM возвращает JSON в markdown блоках (```json), которые не всегда корректно очищаются

**Влияние:**
- Fallback механизм работает (возвращает пустой анализ), система не падает
- Но система не может определить боевые ситуации, квесты и опыт в этих случаях
- Это влияет на автоматическое определение боевых ситуаций и начисление опыта

**Текущее решение:**
- ✅ Fallback механизм реализован (возвращает пустой анализ вместо ошибки)
- ✅ Многоуровневая очистка JSON (cleanJSONResponse → tryRepairTruncatedJSON → aggressiveJSONClean)
- ⚠️ Но проблема все еще возникает периодически

**Рекомендации по улучшению:**
- Увеличить `max_tokens` для DM Analyzer (сейчас 512) - возможно, JSON обрезается из-за лимита токенов
- Улучшить промпт с более четкими инструкциями о завершении JSON
- Добавить проверку на обрезанный JSON и автоматическое завершение структуры
- Рассмотреть использование streaming API для получения полного ответа
- Добавить метрики для мониторинга частоты ошибок парсинга

**Файлы для изменения:**
- `internal/game/application/dm_analyzer/analyze_dm_response.go:142` - увеличить max_tokens
- `internal/game/application/dm_analyzer/analyze_dm_response.go` - улучшить логику восстановления обрезанного JSON

**Статус:** ⚠️ Требует улучшения (не критично, но влияет на функциональность)

**Связано:** Логи production, TASKS.md #2 (частично решено, но требует доработки)
