## 🚨 Активные риски (P0-P2 приоритезация)

### P0 — DM Analyzer: Усеченные JSON ответы (КРИТИЧНО)
- **Симптом**: JSON обрывается посередине (`"items_received":[`, `"npc_met":n`), вызывает 6 retry и fallback
- **Влияние**: Location events не генерируются, анализ боя некорректный, бой может не стартовать
- **Метрики**: `analyzer_json_empty_json count=6`, высокая частота fallback-сценариев
- **Action items**:
  - Улучшить prompt DM Analyzer для полного JSON ответа
  - Увеличить лимит токенов для analyzer (текущий 4096 недостаточен)
  - Добавить post-validation JSON перед отправкой в LLM
  - Улучшить `tryRepairTruncatedJSON` для массивов и объектов
- **Как проверить**: DM Analyzer всегда возвращает валидный JSON без усечений

### P0 — Combat Detection: Неправильное определение боя (КРИТИЧНО)
- **Симптом**: `combat_detected=false` при явных атаках ("гоблин атакует", "ранение")
- **Влияние**: Бой не начинается автоматически, ломает боевую систему
- **Тесты**: FAIL в `TestTelegramGameplay_BotSimulation_LocationEvent_FirstVisit`
- **Action items**:
  - Расширить `detectsCombatMarker` ключевыми словами на русском
  - Улучшить prompt с примерами распознавания боя
  - Добавить fallback анализ для извлечения врагов из текста
  - Улучшить `validateCombatAnalysis` для битых полей врагов
- **Как проверить**: Все combat detection тесты PASS, бой стартует при явных признаках атаки

### P0 — Утечка информации о ловушках в DM текст (КРИТИЧНО)
- **Симптом**: DM предупреждает о ловушках заранее ("Ловушка в замке древних теней...")
- **Влияние**: Ломает погружение, игрок знает о ловушках до взаимодействия
- **Причина**: Analyzer просачивает внутренние триггеры в narrative
- **Action items**:
  - Исправить analyzer-first логику: ловушки активируются только при действиях игрока
  - Добавить guardrail: запрет просачивания внутренних триггеров
  - Ловушки → проверка навыка → тогда предупреждение/активация
- **Как проверить**: DM не предупреждает о ловушках заранее

### P1 — Battlefield Command: Нестабильность/не работает
- **Симптом**: Команда `/battlefield` не отображает информацию о бое
- **Влияние**: Нет прозрачности боя, сложно играть и отлаживать
- **Action items**:
  - Аудит кода команды `/battlefield`
  - Исправить обработку результатов от `GetBattlefieldStatusTool`
  - Добавить поддержку разных форматов (table/compact/detailed)
  - Проверить логику "нет активного боя"
- **Как проверить**: `/battlefield` корректно показывает участников, HP, статусы

### P1 — Оптимизация частоты генерации изображений DM
- **Симптом**: DM слишком часто использует генерацию изображений
- **Влияние**: Перерасход токенов, замедление ответов, раздражает игроков
- **Action items**:
  - Добавить rate limiting для изображений (макс N за сессию/час)
  - Приоритизировать изображения для ключевых моментов (боссы, важные локации)
  - Настроить DM prompt: "Используй изображения sparingly"
  - Добавить текстовый fallback для частых генераций
- **Как проверить**: DM использует изображения только для важных сцен

### P2 — Location Events: Отсутствие в DM prompt
- **Симптом**: Events создаются но не используются в следующем ответе DM
- **Влияние**: Игрок не видит результатов location events
- **Action items**:
  - Проверить индексацию world_events в RAG
  - Убедиться что events попадают в DM контекст
  - Исправить логику извлечения из истории/RAG
- **Как проверить**: Location events влияют на следующие ответы DM

## ✅ Реализованные риски (история исправлений)

### JSON Stability Crisis ✅
- **Решено**: Улучшен `tryRepairTruncatedJSON`, уменьшен лимит токенов до 4096, добавлена pre-validation
- **Результат**: Снижено количество truncated JSON, но P0 проблема остается

### Combat Detection Failure ✅
- **Решено**: Добавлены ключевые слова, улучшен prompt, расширенный fallback анализ
- **Результат**: Улучшена детекция, но все еще FAIL в тестах

### Location events integration gap ✅
- **Решено**: Подключены `world_events` в DM контекст, проиндексированы в RAG
- **Результат**: Events попадают в prompt, но JSON проблемы мешают генерации

### GigaChat timeouts и rate limit логика ✅
- **Решено**: Увеличен timeout до 3 минут, исправлена интерпретация timeout vs rate limit
- **Результат**: Стабильная генерация изображений

### PostgreSQL graceful shutdown ✅
- **Решено**: Добавлен stop_grace_period, улучшена логика shutdown в main.go
- **Результат**: Нет automatic recovery при запуске

### Telegram polling EOF ошибки ✅
- **Решено**: Уменьшен timeout до 30 секунд, добавлена обработка EOF
- **Результат**: Стабильное polling без частых ошибок

### Battlefield Command Broken ✅
- **Решено**: Аудит кода, исправлена обработка результатов, поддержка форматов
- **Результат**: Команда работает для активных боев
