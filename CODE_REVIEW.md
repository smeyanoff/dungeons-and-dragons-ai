## ⚠️ Текущие проблемы (Backlog)

### 1. Отслеживание текущей локации игрока

**Приоритет:** Низкий  
**Источник:** TODO комментарий в коде  
**Статус:** 📋 **В BACKLOG** (TASKS.md CODE-3)

**Проблема:**  
В `handle_action.go:241` есть TODO:
```go
CurrentLocationID: nil, // TODO: добавить отслеживание текущей локации игрока
```

**Влияние:**  
Проверка мировых событий (`CheckWorldEvents`) не может учитывать текущую локацию игрока, что может привести к неточным событиям.

**Решение:**
- Добавить поле `CurrentLocationID` в `Player` или `GameSession`
- Обновлять локацию при перемещении игрока (извлечение из DM ответа)
- Использовать при проверке мировых событий для локационных событий

**Файлы:**
- `internal/game/domain/player/player.go` - добавить `CurrentLocationID`
- `internal/game/application/player_action/handle_action.go:241` - обновить TODO
- `internal/game/application/world_event/check_world_events.go` - использовать локацию игрока

**Связанные документы:**
- TASKS.md: Приоритет 3, задача CODE-3

### 2. Дублирование структур Location и NPC

**Приоритет:** Низкий  
**Источник:** Архитектурный анализ  
**Статус:** 📋 **В BACKLOG** (TASKS.md CODE-5)

**Проблема:**  
Две версии структур в разных пакетах:
- `internal/game/domain/location/location.go` ↔ `internal/game/domain/world/location.go`
- `internal/game/domain/npc/npc.go` ↔ `internal/game/domain/world/npc.go`

**Влияние:**  
Возможна потеря данных при конвертации между структурами.

**Решение:**  
- Объединить структуры в единые domain модели в `internal/game/domain/world/`
- Обновить все места использования для работы с едиными структурами
- Удалить дублирующиеся структуры

**Связанные документы:**
- TASKS.md: Приоритет 3, задача CODE-5

## ⚠️ Не критичные проблемы (из тестов и обратной связи)

### 1. LLM иногда возвращает невалидный JSON

**Приоритет:** Низкий  
**Источник:** TESTING_REPORT.md, FEEDBACK.md  
**Статус:** ⚠️ **Работает, но можно улучшить**

**Проблема:**  
LLM иногда возвращает невалидный JSON для локаций и других структур.

**Влияние:**  
Не критично, repair механизм работает и исправляет JSON автоматически.

**Решение:**  
Улучшить промпты для более стабильного JSON.

**Связанные документы:**
- TESTING_REPORT.md: Проблема #2
- FEEDBACK.md: Проблема #1

---

### 2. LLM создает врагов без имени

**Приоритет:** Низкий  
**Источник:** TESTING_REPORT.md, FEEDBACK.md  
**Статус:** ⚠️ **Требует улучшения промптов**

**Проблема:**  
LLM иногда создает врагов без имени, что приводит к пропуску врага и не началу боя.

**Влияние:**  
Не критично, враг пропускается, бой не начинается.

**Решение:**  
Улучшить промпты для DM, чтобы всегда указывать имя врага.

**Связанные документы:**
- TESTING_REPORT.md: Проблема #3
- FEEDBACK.md: Проблема #2

---

### 3. Таймаут при индексации RAG

**Приоритет:** Низкий  
**Источник:** TESTING_REPORT.md, FEEDBACK.md  
**Статус:** ⚠️ **Требует оптимизации**

**Проблема:**  
Редкие таймауты (`context deadline exceeded`) при индексации DM событий в RAG.

**Влияние:**  
Не критично, событие сохраняется в БД, но не индексируется в RAG.

**Решение:**  
Увеличить таймаут или оптимизировать процесс индексации.

**Связанные документы:**
- TESTING_REPORT.md: Проблема #4
- FEEDBACK.md: Проблема #3
