2. **✅ Ответы DM на игровые действия:**
   - LLM генерирует подробные и интересные описания локаций
   - Пример: "Вы заходите в просторную комнату храма светлых богов, украшенную сияющими фресками и свечением древних магических кристаллов..."

3. **✅ Боевая система:**
   - LLM корректно определяет начало боя
   - Генерирует описания атак: "Воин быстро выхватывает меч и атакует ближайшего гоблина, издавая боевой клич"
   - Бой работает корректно, враги повержены

4. **✅ RAG система:**
   - События успешно индексируются в RAG
   - Контекст извлекается для последующих действий
   - Редкие таймауты при индексации (не критично)

### Проблемы LLM (не критичные):

1. **LLM иногда возвращает невалидный JSON:**
   - Предупреждение: `LLM response for locations is not valid JSON, attempting to repair`
   - **Решение:** Repair механизм работает и исправляет JSON
   - **Рекомендация:** Улучшить промпты для более стабильного JSON

2. **LLM создает врагов без имени:**
   - Предупреждение: `Skipping enemy without name (HP: 4, AC: 15)`
   - **Влияние:** Враг пропускается, бой не начинается
   - **Рекомендация:** Улучшить промпты для DM, чтобы всегда указывать имя врага

3. **Таймаут при индексации RAG:**
   - Предупреждение: `context deadline exceeded` при индексации DM события
   - **Влияние:** Событие сохраняется в БД, но не индексируется в RAG
   - **Рекомендация:** Увеличить таймаут или оптимизировать процесс индексации

### Общая оценка:
- ✅ **Отлично:** LLM генерирует качественные, интересные и подробные ответы
- ✅ **Хорошо:** Системы работают стабильно с реальными LLM ответами

## Обратная связь от интеграционных тестов (2026-01-19 20:20:00)

1. **КРИТИЧНО: Не удается получить реальные ответы LLM из-за TLS сертификата**
   - **Проблема:** Все запросы к GigaChat API падают с ошибкой `tls: failed to verify certificate: x509: certificate signed by unknown authority`
   - **Влияние:** 
     - Не удается протестировать реальные ответы LLM
     - Не удается создать игру через LLM
     - Не удается получить ответы DM на игровые действия
     - RAG система не может индексировать события (не может получить embeddings)
   - **Попытки подключения:**
     - Множественные попытки получения токена (каждая падает с TLS ошибкой)
     - Retry механизм работает, но не помогает (проблема на уровне TLS)
   - **Решение:** 
     - Добавить корневой сертификат Сбербанка в систему
     - Или настроить `SSL_CERT_FILE` в окружении
     - Или добавить поддержку загрузки сертификата из `build/certs/linux_russian_trusted_root_ca_pem/` в код клиента GigaChat

## 🐛 Актуальные проблемы (требуют решения)

**Статус:** ⚠️ **Обнаружены проблемы с отображением порядка ходов и автоматическими ходами врагов**

> **Примечание:** Все ранее обнаруженные критические проблемы (#1, #2, #3, #4) были решены в Январе 2025 и перенесены в раздел "Решенные проблемы" ниже.

### 1. Не отображаются игрок и спутники в порядке ходов боя
**Проблема:** В сообщении "⚔️ Бой начался! Порядок ходов:" отображаются только враги, но не отображаются игрок и его спутники (например, Хандрик).

**Пример из диалога:**
- Сообщение показывает: "2. страж древних развалин (инициатива: 9)"
- Но не показывает: "1. [Имя игрока] (инициатива: X)" и "2. Хандрик (инициатива: Y)"
- В реальности в бою есть игрок и спутник Хандрик, но они не отображаются в порядке ходов

**Приоритет:** Высокий ⚠️  
**Статус:** Требует исправления

**Возможные причины:**
1. Спутники (NPC companions) не добавляются в `Combat.Participants` при создании боя
2. В методе `GetInitiativeOrderMessage()` неправильно обрабатываются участники боя
3. Участники-игроки пропускаются из-за фильтрации по `IsAlive()` или другого условия

**Решение:**
- Проверить, что при создании боя все участники (игрок + спутники + враги) добавляются в `Combat.Participants`
- Исправить `GetInitiativeOrderMessage()` для отображения всех живых участников
- Убедиться, что спутники (NPC companions) создаются как `CombatParticipant` с `IsPlayer=false`, но с соответствующими характеристиками

**Технические детали:**
- Проверить `handleCombatStart()` в `analyze_dm_response.go` - добавляются ли спутники в Participants
- Исправить `GetInitiativeOrderMessage()` в `combat.go` - должен показывать всех участников по порядку инициативы

### 2. Враги не выполняют ходы автоматически
**Проблема:** Когда текущий ход принадлежит врагу (например, "🎯 Текущий ход: страж древних развалин"), DM не описывает автоматически действие врага и не выполняет его атаку.

**Пример из диалога:**
- Текущий ход: "страж древних развалин"
- Но DM не пишет описание действия стража и не выполняет автоматическую атаку
- Игрок ожидает, что враг атакует автоматически на свой ход

**Приоритет:** Высокий ⚠️  
**Статус:** Требует исправления

**Возможные причины:**
1. Нет механизма автоматического выполнения ходов врагов
2. DM не получает информацию о том, что текущий ход врага
3. Нет инструкций для DM о необходимости описывать действия врагов на их ходы
4. Не вызываются tools для автоматической атаки врагов

**Решение:**
- При начале хода врага автоматически вызывать DM для описания действия и атаки
- Использовать `PerformAttackTool` для автоматической атаки врага по игроку
- Добавить инструкции для DM: "Если текущий ход принадлежит врагу, ОБЯЗАТЕЛЬНО опиши его действие и используй `perform_combat_attack` для атаки по игроку"
- После хода игрока автоматически переходить к следующему ходу (врага) и генерировать ответ DM

**Технические детали:**
- В `handle_action.go` после обработки действия игрока проверять, чей следующий ход
- Если следующий ход врага - автоматически генерировать ответ DM с описанием действия врага и его атаки
- Интегрировать с `NextTurn()` для перехода к следующему ходу
- Использовать `PerformCombatAttackTool` для автоматической атаки врагов
