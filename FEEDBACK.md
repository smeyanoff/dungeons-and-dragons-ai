## Главный продуктовый сигнал (P0)

### Проверки нельзя “починить промптом”
- При детальных инструкциях DM начинает **спамить проверками**.
- Ожидание игроков: проверки **редкие и значимые**.
- Вывод: контроль через **DM tools + runtime guardrails** (budget/cooldown/anti‑trivial + обязательные reason/stakes).

## Актуальные проблемы (требуют решения)

### 1) Технические сообщения tools видны игроку (P1)
- “Внутренняя кухня” (служебные строки) попадает в ответ DM → ломает погружение.
- Ожидание: игрок видит только художественный текст + понятный итог (без тех. деталей).

### 2) `/battlefield` не работает/нестабилен (P1)
- Нет прозрачности боя, сложнее отлаживать поведение.

## Сигналы качества (держать курс)
- Атмосферные описания, связная генерация мира.
- Бой в целом работает (инициатива/атаки/урон/победа).
- История/RAG помогает удерживать контекст (когда индексация стабильна).

---

## Инженерные алерты (влияют на UX/стабильность)
- **Невалидный JSON от LLM** (особенно `InitCampaign`) → падения/ретраи.
- **DM Analyzer** иногда возвращает `{}` или “битые” поля (пример: `combat_detected=true`, но `enemy.name=""`) → бой не стартует.
- **RAG индексация**: редкие таймауты (событие есть в БД, но не в индексе).
- **GigaChat token expiry** выглядит неверным (подозрение: путаница единиц `expires_in`).
- **Image download 403** → нестабильная генерация изображений (права/скоуп/разные окружения).

## Обратная связь от интеграционного прогона (2026-01-21)

1. **DM Analyzer: пустой JSON `{}`** встречался многократно в прогоне (счётчик `analyzer_json_empty_json` рос до 9). Это может приводить к пропуску боёв/квестов/награды и делает поведение непредсказуемым.

2. **“Внутренняя кухня” проверок видна в тексте DM**: в ответах появлялись строки вида “Выполняется проверка ...”, “Оценивается результат ...”. Для игрока это выглядит как тех. трассировка — нужно санитизировать/запретить.

3. **InitCampaign/World generation: частые JSON-repair/fallback** по `locations`/`connections`/`predefined checks` (много предупреждений “not valid JSON → repair → retry”). Даже если игра продолжается, это заметный сигнал нестабильности контракта.

## Сигналы по реальному LLM из интеграционного лога (2026-01-21)

1. **Подозрение на неверные единицы `expires_in` у GigaChat**: в логах встречается аномально большое значение времени жизни токена (похоже на миллисекунды, интерпретированные как секунды). Это усиливает сигнал “token expiry выглядит неверным”.

2. **DM Analyzer: пустой JSON `{}`**: даже при нормальном DM ответе анализ иногда возвращает `{}` — это ведёт к пропускам триггеров (бой/квест/награды) и делает поведение непредсказуемым.

3. **Player-facing утечки tool‑контента**: встречаются ответы/история, где видны `request_ability_check`/служебные подсказки (“ожидаемый ввод /roll ...”). Для игрока это выглядит как трассировка и ломает погружение.

## Обратная связь от интеграционных тестов (2026-01-21 21:48:55)

1. **InitCampaign: частые случаи невалидного JSON** (NPCs / connections): приходится делать `jsonrepair`, ретраи, а для `connections` местами срабатывает fallback. Это ухудшает качество мира и может ломать навигацию.

2. **DM Analyzer: “битые” враги в анализе**: встречается `combat_detected=true`, но `enemies[0].name=""` → пайплайн пропускает врага и затем не может стартовать бой (`need at least 2 participants`). Это делает боевое поведение непредсказуемым.

3. **GigaChat image**: генерация ок, но **скачивание изображения падает 403 Permission denied**. Для игрока это выглядит как “карта/картинка не загрузилась”, хотя текстовый fallback есть.
