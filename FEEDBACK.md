### 1. Не отображаются игрок и спутники в порядке ходов боя
**Проблема:** В сообщении "⚔️ Бой начался! Порядок ходов:" отображаются только враги, но не отображаются игрок и его спутники (например, Хандрик).

**Пример из диалога:**
- Сообщение показывает: "2. страж древних развалин (инициатива: 9)"
- Но не показывает: "1. [Имя игрока] (инициатива: X)" и "2. Хандрик (инициатива: Y)"
- В реальности в бою есть игрок и спутник Хандрик, но они не отображаются в порядке ходов

**Приоритет:** Высокий ⚠️  
**Статус:** Требует исправления

**Возможные причины:**
1. Спутники (NPC companions) не добавляются в `Combat.Participants` при создании боя
2. В методе `GetInitiativeOrderMessage()` неправильно обрабатываются участники боя
3. Участники-игроки пропускаются из-за фильтрации по `IsAlive()` или другого условия

**Решение:**
- Проверить, что при создании боя все участники (игрок + спутники + враги) добавляются в `Combat.Participants`
- Исправить `GetInitiativeOrderMessage()` для отображения всех живых участников
- Убедиться, что спутники (NPC companions) создаются как `CombatParticipant` с `IsPlayer=false`, но с соответствующими характеристиками

**Технические детали:**
- Проверить `handleCombatStart()` в `analyze_dm_response.go` - добавляются ли спутники в Participants
- Исправить `GetInitiativeOrderMessage()` в `combat.go` - должен показывать всех участников по порядку инициативы

### 2. Враги не выполняют ходы автоматически
**Проблема:** Когда текущий ход принадлежит врагу (например, "🎯 Текущий ход: страж древних развалин"), DM не описывает автоматически действие врага и не выполняет его атаку.

**Пример из диалога:**
- Текущий ход: "страж древних развалин"
- Но DM не пишет описание действия стража и не выполняет автоматическую атаку
- Игрок ожидает, что враг атакует автоматически на свой ход

**Приоритет:** Высокий ⚠️  
**Статус:** Требует исправления

**Возможные причины:**
1. Нет механизма автоматического выполнения ходов врагов
2. DM не получает информацию о том, что текущий ход врага
3. Нет инструкций для DM о необходимости описывать действия врагов на их ходы
4. Не вызываются tools для автоматической атаки врагов

**Решение:**
- При начале хода врага автоматически вызывать DM для описания действия и атаки
- Использовать `PerformAttackTool` для автоматической атаки врага по игроку
- Добавить инструкции для DM: "Если текущий ход принадлежит врагу, ОБЯЗАТЕЛЬНО опиши его действие и используй `perform_combat_attack` для атаки по игроку"
- После хода игрока автоматически переходить к следующему ходу (врага) и генерировать ответ DM

**Технические детали:**
- В `handle_action.go` после обработки действия игрока проверять, чей следующий ход
- Если следующий ход врага - автоматически генерировать ответ DM с описанием действия врага и его атаки
- Интегрировать с `NextTurn()` для перехода к следующему ходу
- Использовать `PerformCombatAttackTool` для автоматической атаки врагов

### ✅ Решенные проблемы (обновлено Январь 2025)

#### 1. Боевая система не работает во время боя - РЕШЕНО ✅
**Проблема:** Когда начинается бой, DM описывает действия, но не наносит урон и игрок не может атаковать.

**Решение (реализовано Январь 2025):**
- ✅ DM сам определяет атакующие действия через LLM и использует tool `perform_combat_attack` (TASKS.md #55)
- ✅ DM наносит урон через tool `apply_damage` при атаках врагов (TASKS.md #53, #56)
- ✅ Результаты атак явно отображаются в чате перед ответом DM (TASKS.md #54)
- ✅ Добавлена команда `/attack` для явной атаки (TASKS.md #55)
- ✅ Боевые действия игрока обрабатываются автоматически через LLM-driven tools

**Приоритет:** Критический  
**Статус:** ✅ **РЕШЕНО** (Январь 2025) - см. TASKS.md #55, #56, #53, #54

**Реализовано:**
- Создан `PerformCombatAttackTool` для обработки атак игрока
- Создан `ApplyDamageTool` для нанесения урона от DM
- Результаты combat tools автоматически добавляются к ответу DM
- Инструкции для DM о использовании combat tools добавлены в контекст RAG
