## 🐛 Актуальные проблемы (требуют решения)

**Статус:** ⚠️ **Обнаружена критическая проблема с расчетом урона в бою**

### 1. Неправильный расчет урона и отображение HP/AC/броска в бою
**Проблема:** При атаке в бою система показывает неправильные значения HP, AC и броска атаки:

- **Неправильное HP после урона:** У лучника было 2 HP, после атаки с уроном 4 система показывает "HP маски лучника: 0/0 HP" вместо правильного значения (должно быть 0/6, так как было 2 HP, нанесено 4 урона)
- **Бросок атаки показывает 0:** Система показывает "бросок: 0 против AC 0" - это неправильно, бросок и AC не должны быть 0
- **AC показывает 0:** AC цели (монстра) показывает 0 вместо реального значения (должно быть 12 или другое значение из MonsterAC)

**Пример из диалога:**
- Лучник имел: 2/6 HP
- Игрок атакует и наносит 4 урона
- Система показывает: "⚔️ smeyanof атакует маска лучника и попадает! (бросок: 0 против AC 0)"
- Система показывает: "HP маски лучника: 0/0 HP" ❌ (неправильно, должно быть 0/6)
- В следующем ответе DM показывает: "HP маски лучника: 2/6" (тоже неправильно, должно быть 0/6)

**Приоритет:** Критический ⚠️  
**Статус:** Требует срочного исправления

**Возможные причины:**
1. Монстр не загружается корректно из БД (MonsterHP, MonsterMaxHP, MonsterAC не загружаются через Preload)
2. При применении урона через `ApplyDamageTool` состояние не обновляется корректно
3. При получении данных для отображения (`GetHP()`, `GetAC()`) монстр не загружается из БД
4. `CombatParticipant` не сохраняется/не загружается корректно после применения урона
5. Race condition при конкурентном доступе к `CombatParticipant` без синхронизации

**Технические детали:**
- Нужно проверить загрузку `CombatParticipant` с `Preload` для всех полей
- Проверить сохранение состояния боя после применения урона
- Проверить корректность загрузки MonsterHP, MonsterMaxHP, MonsterAC из БД
- Проверить синхронизацию доступа к `CombatParticipant` при чтении/записи

### 2. DM выдумывает союзников/товарищей в бою, которых нет
**Проблема:** DM описывает союзников/товарищей игрока в бою, которых нет в реальной игровой сессии или среди участников боя.

**Пример из диалога:**
- Игрок: "затаись и подожди пока лучники подойдут"
- DM: "...твои товарищи выскакивают из укрытия справа и слева, обрушивая внезапную атаку на ничего не подозревающих врагов"
- Реальность: Игрок один в бою, нет союзников/товарищей
- Проблема: DM выдумывает союзников, которых нет в реальной игровой сессии

**Приоритет:** Высокий ⚠️  
**Статус:** Требует исправления

**Возможные причины:**
1. DM не получает информацию о том, что игрок один в бою
2. Информация о количестве игроков в сессии не включается в контекст для DM
3. Нет явного указания DM использовать только реальных участников боя из `Combat.Participants`
4. DM генерирует действия от лица несуществующих NPC/союзников

**Решение:**
- Добавить в контекст RAG явное указание количества игроков в сессии: "Количество игроков: 1 (игрок один)"
- Добавить инструкцию для DM: "Используй ТОЛЬКО реальных участников боя из списка выше. Не выдумывай союзников или товарищей, которых нет в списке участников боя"
- При перечислении участников боя явно указывать, сколько игроков и сколько врагов
- Улучшить промпт DM для использования только реальных данных из БД

**Технические детали:**
- Расширить `RAGContextBuilder.BuildContext()` для подсчета игроков в сессии
- Добавить явное указание в контекст: "Игроков в бою: X, Врагов: Y"
- Добавить инструкцию DM: "Не упоминай союзников или товарищей, если их нет в списке участников боя"
- Проверить, что информация о `Combat.Participants` корректно включает всех реальных участников

### 3. DM никогда не просит пользователя бросить кубик, бросание кубика бесполезно
**Проблема:** DM не запрашивает у игрока броски кубиков для проверок характеристик, из-за чего система бросания кубиков (`/roll`) бесполезна.

**Проблемы:**
- DM никогда не просит игрока бросить кубик для проверок характеристик (Ability Checks, Saving Throws)
- Команда `/roll` существует, но DM не использует результаты бросков
- Бросание кубика по сути бесполезно - результаты бросков не учитываются в игре
- DM не сравнивает результаты бросков с DC (сложностью) для определения успеха/неудачи
- Нет связи между бросками кубиков и игровой механикой

**Приоритет:** Высокий ⚠️  
**Статус:** Требует срочного исправления

**Возможные причины:**
1. DM не получает инструкции о необходимости запрашивать броски кубиков
2. Нет инструментов (tools) для запроса проверок характеристик
3. DM не знает, когда нужно запрашивать броски кубиков
4. Нет механизма для обработки результатов бросков игрока
5. Промпт DM не содержит инструкций о проверках характеристик

**Решение:**
- Создать MCP-style tools для запроса проверок (`request_ability_check`, `request_saving_throw`)
- Добавить инструкции для DM о необходимости запрашивать броски кубиков
- Создать tool для оценки результатов бросков (`evaluate_check`)
- Интегрировать результаты `/roll` с оценкой проверок
- Обновить промпт DM для явного упоминания необходимости запроса бросков

**Технические детали:**
- Создать `RequestAbilityCheckTool`, `RequestSavingThrowTool`, `EvaluateCheckTool`
- Добавить в контекст RAG инструкции для DM: "Когда действие игрока требует проверки характеристики, ОБЯЗАТЕЛЬНО запроси бросок кубика через tool `request_ability_check`"
- Обрабатывать результаты `/roll` через `EvaluateCheckTool` для сравнения с DC
- Интегрировать результаты бросков в ответы DM

### ✅ Решенные проблемы (обновлено Январь 2025)

#### 1. Боевая система не работает во время боя - РЕШЕНО ✅
**Проблема:** Когда начинается бой, DM описывает действия, но не наносит урон и игрок не может атаковать.

**Решение (реализовано Январь 2025):**
- ✅ DM сам определяет атакующие действия через LLM и использует tool `perform_combat_attack` (TASKS.md #55)
- ✅ DM наносит урон через tool `apply_damage` при атаках врагов (TASKS.md #53, #56)
- ✅ Результаты атак явно отображаются в чате перед ответом DM (TASKS.md #54)
- ✅ Добавлена команда `/attack` для явной атаки (TASKS.md #55)
- ✅ Боевые действия игрока обрабатываются автоматически через LLM-driven tools

**Приоритет:** Критический  
**Статус:** ✅ **РЕШЕНО** (Январь 2025) - см. TASKS.md #55, #56, #53, #54

**Реализовано:**
- Создан `PerformCombatAttackTool` для обработки атак игрока
- Создан `ApplyDamageTool` для нанесения урона от DM
- Результаты combat tools автоматически добавляются к ответу DM
- Инструкции для DM о использовании combat tools добавлены в контекст RAG
