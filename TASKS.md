### Задача #64: Исправление неправильного расчета урона и отображения HP/AC/броска в бою
**Статус:** ✅ **ЗАВЕРШЕНО** (Январь 2025)  
**Приоритет:** 🔴 Критический (блокирует боевую систему)  
**Оценка:** 4-6 часов  
**Ответственный:** Backend разработчик

**Описание:**  
Критическая ошибка - система показывает неправильные значения HP, AC и броска атаки при боевых действиях. После нанесения урона система показывает "HP: 0/0" вместо корректных значений. AC и бросок атаки показывают 0 вместо реальных значений.

**Проблема:**  
- После атаки с уроном система показывает неправильные HP/AC (например, было 2/6 HP, нанесено 4 урона → показывает "HP: 0/0" вместо "0/6")
- Бросок атаки показывает "бросок: 0 против AC 0" - неправильно
- AC монстра показывает 0 вместо реального значения из MonsterAC
- DM Analyzer может создавать бой с HP=0 для врагов

**Решение:**
- Проверить загрузку `CombatParticipant` из БД - добавить `Preload("Participants.Character.Stats")` для корректной загрузки характеристик
- Проверить сохранение состояния боя после применения урона через `ApplyDamageTool`
- Исправить загрузку MonsterHP, MonsterMaxHP, MonsterAC из БД перед расчетом атаки
- Добавить валидацию значений перед отображением (HP/AC не должны быть 0 для живых монстров)
- Исправить создание участников боя с HP=0 в DM Analyzer

**Технические детали:**
- Проверить `CombatRepository.GetActiveBySessionID()` - добавить `Preload("Participants.Character.Stats")`
- Проверить `ApplyDamageTool.Execute()` - сохраняет ли состояние после применения урона
- Проверить `PerformCombatAttackTool` - правильно ли загружает характеристики участников
- Проверить `handleCombatStart` в DM Analyzer - использовать значения по умолчанию если HP <= 0

**Файлы для изменения:**
- `internal/game/infrastructure/persistence/combat.go` - добавить Preload для Stats
- `internal/game/application/dm_tools/combat_tool.go` - проверка сохранения после урона
- `internal/game/application/dm_analyzer/analyze_dm_response.go` - исправление создания участников
- `internal/game/domain/combat/combat.go` - методы GetHP(), GetAC()

**Критерии приемки:**
- [x] Все характеристики (HP, AC, бросок атаки) корректно отображаются после применения урона
- [x] Монстры создаются с корректными HP/AC из данных или значений по умолчанию
- [x] Состояние боя корректно сохраняется после применения урона
- [x] Тесты проверяют корректность загрузки и отображения характеристик

**Реализация:**
- Добавлен `Preload("Participants.Character.Stats")` в `CombatRepository.GetActiveBySessionID()` и `GetByID()` для корректной загрузки характеристик
- Проверено сохранение состояния боя после применения урона через `ApplyDamageTool` - работает корректно
- Проверено создание участников боя в DM Analyzer - использует значения по умолчанию для HP/AC если <= 0

### Задача #66: Исправление блокировки подбора предметов из мира валидатором
**Статус:** ✅ **ЗАВЕРШЕНО** (Январь 2025)  
**Приоритет:** 🔴 Критический (блокирует базовое взаимодействие с миром)  
**Оценка:** 1-2 часа  
**Ответственный:** Backend разработчик

**Описание:**  
Валидатор действий ошибочно блокирует действие "взять" для предметов из мира, считая что предмет должен быть в инвентаре. Это блокирует подбор предметов из мира игроком.

**Проблема:**  
- Игрок хочет взять предмет из мира (лежит на сундуке, на земле, описан DM)
- Валидатор блокирует действие "взять" с ошибкой: "У вас нет предметов в инвентаре для действия 'взять'"
- Валидатор не различает "взять [предмет из мира]" (подобрать) и "использовать [предмет из инвентаря]"

**Решение:**
- Убрать "взять" из списка проверяемых действий в `checkEmptyInventoryItemUsage()` (строка 140)
- Действие "взять" должно означать подбор предмета из мира, а не использование предмета из инвентаря
- Для подбора предметов из мира использовать механизм автоматического добавления предметов (#4) или команду `/pickup`

**Технические детали:**
- Убрать "взять" из `itemActions` в `checkEmptyInventoryItemUsage()` функции
- Действие "взять" должно пропускаться валидатором и обрабатываться DM через автоматическое добавление предметов
- Оставить проверку для "использовать", "применить", "выпить", "надеть" и других действий использования предметов из инвентаря

**Файлы для изменения:**
- `internal/game/application/player_action/action_validator.go` - строка 140, убрать "взять" из списка

**Критерии приемки:**
- [x] Действие "взять [предмет]" не блокируется валидатором при пустом инвентаре
- [x] Подбор предметов из мира работает корректно через автоматическое добавление предметов
- [x] Проверка использования предметов из инвентаря продолжает работать
- [x] Тесты проверяют различие между подбором и использованием предметов

**Реализация:**
- Убрано "взять" из списка проверяемых действий в `ActionValidator.checkEmptyInventoryItemUsage()`
- Действие "взять" теперь означает подбор предмета из мира, а не использование из инвентаря
- Проверка использования предметов из инвентаря ("использовать", "применить", "выпить" и т.д.) продолжает работать

### Задача #65: Предотвращение выдумывания союзников/товарищих DM в бою
**Статус:** ✅ **ЗАВЕРШЕНО** (Январь 2025)  
**Приоритет:** 🔴 Критический (консистентность боевой системы)  
**Оценка:** 2-3 часа  
**Ответственный:** Backend разработчик

**Описание:**  
DM описывает союзников/товарищей игрока в бою, которых нет в реальной игровой сессии. DM должен использовать только реальных участников боя из `Combat.Participants`.

**Проблема:**  
- DM описывает союзников/товарищей игрока в бою, которых нет в реальной игровой сессии
- DM генерирует действия от лица несуществующих NPC/союзников
- Игрок может быть один в бою, но DM упоминает "товарищей" или "союзников"

**Решение:**
- Добавить в контекст RAG явное указание количества игроков в сессии: "Количество игроков: 1 (игрок один)"
- При перечислении участников боя явно указывать: "Игроков в бою: X, Врагов: Y"
- Добавить инструкцию для DM: "Используй ТОЛЬКО реальных участников боя из списка выше. Не выдумывай союзников, товарищей или NPC, которых нет в списке участников боя"

**Технические детали:**
- Расширить `RAGContextBuilder.BuildContext()` для подсчета игроков в сессии (`len(gs.Players)`)
- В секции "--- Текущий бой ---" добавить: "Игроков в бою: X, Врагов: Y"
- Добавить явное указание: "Игрок один в бою" если `len(gs.Players) == 1` и `participant.IsPlayer` только один
- Добавить инструкцию DM в контекст: "ВАЖНО: Не упоминай союзников, товарищей или других NPC, если их нет в списке участников боя выше"

**Реализация:**
- Добавлена информация о количестве игроков в сессии в `RAGContextBuilder.BuildContext()`
