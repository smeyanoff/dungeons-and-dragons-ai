### Задача #1: Исправление integer overflow conversions (CWE-190)
**Статус:** ✅ **Завершено** (Январь 2025)  
**Приоритет:** 🔴 Критический (безопасность)  
**Оценка:** 2-3 часа  
**Ответственный:** Backend разработчик

**Описание:**  
Преобразования типов без проверки на переполнение в `qdrant.go` и `auth.go`. Риск: HIGH - Integer overflow может привести к непредсказуемому поведению или уязвимостям безопасности.

**Проблемные места:**
- `internal/rag/infrastructure/vectorstore/qdrant.go:99, 118, 131` - `uint` → `int64`
- `pkg/gigachat/auth.go:151` - `int` → `uint64` / `uint`

**Решение:**
- Добавить проверки диапазонов перед преобразованием
- Использовать `strconv` для безопасных преобразований
- Добавить валидацию значений перед использованием

**Файлы для изменения:**
- `internal/rag/infrastructure/vectorstore/qdrant.go`
- `pkg/gigachat/auth.go`

**Критерии приемки:**
- [x] Все преобразования типов имеют проверки диапазонов
- [x] Gosec не выдает предупреждений CWE-190 для этих файлов
- [x] Тесты проверяют обработку граничных случаев
- [x] Код работает корректно при больших значениях

**Реализация:**
- Добавлена функция `safeUintToInt64()` в `qdrant.go` для безопасного преобразования uint → int64
- Добавлена валидация `limit` в `Search()` для предотвращения overflow
- Исправлена обработка timestamp в `auth.go`

**Связанные документы:**
- CODE_REVIEW.md: Проблемы безопасности #1
- PROBLEMS.md: #4

### Задача #2: Замена math/rand на crypto/rand в dice.go (CWE-338)
**Статус:** ✅ **Завершено** (Январь 2025)  
**Приоритет:** 🔴 Критический (безопасность)  
**Оценка:** 1-2 часа  
**Ответственный:** Backend разработчик

**Описание:**  
Использование `math/rand` вместо `crypto/rand` в генераторе случайных чисел для костей. Риск: HIGH - Детерминированный генератор может быть предсказуемым.

**Проблемное место:**
- `internal/game/domain/dice/dice.go:60`

**Решение:**
```go
import "crypto/rand"
// Использовать crypto/rand для криптографически стойкого генератора
```

**Файлы для изменения:**
- `internal/game/domain/dice/dice.go`

**Критерии приемки:**
- [x] `math/rand` заменен на `crypto/rand`
- [x] Генерация случайных чисел работает корректно
- [x] Тесты проходят с новым генератором
- [x] Gosec не выдает предупреждений CWE-338

**Реализация:**
- Заменен `math/rand` на `crypto/rand` в `dice.go`
- Создана функция `secureRandomInt()` для криптографически стойкой генерации случайных чисел
- Используется `crypto/rand.Read()` с `binary.BigEndian.Uint64()` для генерации

**Решение:**
- Добавлять информацию о статусе боя в контекст RAG для DM
- Включать явное упоминание статуса боя в промпт DM при активном бое
- Добавлять префикс или индикатор в ответы DM: "⚔️ [В БОЮ] ..." или "⚔️ Бой продолжается. ..."

**Технические детали:**
- Расширить `RAGContextBuilder.BuildContext()` для проверки активного боя через `combatRepo`
- При активном бое добавлять секцию "--- Статус боя ---" с информацией:
  - "В данный момент идет активный бой"
  - Текущий ход
  - Участники боя (кратко: имена и HP)
  - Порядок ходов по инициативе
- Обновить промпт DM: "Если идет активный бой, всегда упомяни это в начале ответа"

**Файлы для изменения:**
- `internal/game/infrastructure/context/rag_context_builder.go` - добавление статуса боя в контекст
- `internal/game/application/dm_analyzer/analyze_dm_response.go` - возможно обновление промпта

**Критерии приемки:**
- [x] Информация о статусе боя автоматически включается в контекст при активном бое
- [x] DM всегда упоминает статус боя в начале ответа во время активного боя
- [x] Индикатор боя явно виден игроку (эмодзи или текст)
- [x] Информация о текущем ходе включена в ответ
- [x] Тесты проверяют включение статуса боя в контекст

**Реализация:**
- Добавлена явная инструкция DM в `rag_context_builder.go` упоминать статус боя в начале ответа
- Обновлен промпт в `buildDMPrompt()` с инструкцией о статусе боя
- Добавлен префикс "⚔️ [В БОЮ]" для явного указания боевой ситуации
