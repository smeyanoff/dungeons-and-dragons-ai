## 🟡 P2 — Игровые механики / техдолг (только если P0/P1 идут по плану)

### P2.1 ⏳ Guardrails проверок (runtime): добавить budget + anti-trivial поверх уже существующего cooldown
- **Источник:** `PRODUCT_IDEAS.md` → P0.4  
- **Факт:** cooldown уже частично реализован; не хватает “budget на сцену” и “anti-trivial”.
- **Что сделать (минимум):**
  - Budget: лимит “существенных” проверок на сцену/короткий период (в сессии/в истории).
  - Anti‑trivial: при низких ставках — автоуспех/описание без броска.
  - Обязательные `reason` + `stakes` → всегда в историю/RAG.
- **Критерии приемки:**
  - DM физически не может заспамить проверками без роста ставок.
  - Логи/история позволяют объяснить “почему проверку отклонили”.

### P2.2 ⏳ Location events v2: “0..N событий” + статусы pending/resolved/expired (после P1.1)
- **Источник:** `PRODUCT_IDEAS.md` → P0.1, P0.5  
- **Что сделать:**
  - Разрешить 0..N событий на локацию (с ограничителем частоты).
  - Ввести состояния (pending/resolved/expired) и правила повторного появления.
  - Дать DM инструмент/правило “как завершать событие” (через историю/инструменты последствий).
- **Критерии приемки:**
  - Игрок регулярно видит “сценки” в локациях, которые не повторяются бесконечно.
  - DM “помнит” исход событий через RAG.
