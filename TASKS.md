## 🚨 Активные задачи

### P0 — Критические ошибки (исправить немедленно) ✅

- **DM Analyzer: truncated JSON ответы от LLM** ✅
  - Симптом: JSON обрывается посередине ключа `{"combat_detected":false,"enemies":[],"quest_completed":false,"quest_failed":false,"quest_title":"","experience_gained":0,"experience_reason":"","items_received"`
  - Улучшить `tryRepairTruncatedJSON` для незавершенных ключей
  - Добавить валидацию JSON структур до отправки в LLM
  - Увеличить maxRetries для DM analyzer

- **Location events integration gap** ✅
  - Симптом: Location events создаются но не попадают в следующий DM prompt
  - Подключить `world_events` в контекст DM (history/RAG/контекст-билдер)
  - Проиндексировать location events в RAG как StoryEvent
  - Перевести тест `telegram_location_event_simulation_test.go` из t.Skip в assert

### P1 — Риски стабильности (высокий приоритет) ✅

- **GigaChat rate limiting (429) влияет на UX** ✅
  - Уменьшить concurrency limit до 2
  - Увеличить initial backoff delay до 5-10 секунд
  - Добавить метрики RPS и 429 rate для мониторинга

- **Image generation: context deadline exceeded** ✅
  - Увеличить таймаут генерации изображений до 300s
  - Улучшить retry логику (меньше retry, но с большим таймаутом)
  - Добавить graceful fallback на текстовое описание

- **DM Analyzer: пустые/битые поля** ✅
  - Улучшить `validateCombatAnalysis` с строгими проверками
  - Добавить fallback логику для битых врагов
  - Увеличить валидацию JSON схемы перед парсингом

- **RAG индексация: редкие провалы памяти** ✅
  - Добавить логирование ошибок индексации с алертами
  - Реализовать graceful fallback на историю из БД
  - Улучшить retry логику для IndexDocument
